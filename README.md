# ⚡ AI-Powered Energy Consumption Forecasting System

Day-ahead electricity demand forecasting for a simulated manufacturing campus, with a business-savings simulation and a live API dashboard. Built with Python and scikit-learn using a realistic simulated dataset (no private utility data needed).

![image alt](https://github.com/guraiml30/AI-Energy-Consumption-Forecasting/blob/a6d95f51733a9b0e4da745946202ce1d87d678e0/Output1.png)

## Problem statement
Utilities, factories and data centers must buy or schedule power a day ahead. Under-forecasting forces expensive spot purchases; over-forecasting wastes money. This project forecasts hourly demand and measures what better forecasts are worth.

## Industry relevance
Smart cities (grid planning), electricity boards (load dispatch), manufacturing plants (peak-demand charges), data centers (cooling and capacity), renewable companies (balancing solar/wind variability).

## Tech stack
Python 3.10+, Pandas, NumPy, scikit-learn (Linear Regression, Random Forest, Gradient Boosting), Matplotlib, Seaborn, Flask + Waitress, Docker.

## Dataset
Two years of hourly data (17,544 rows): `timestamp`, `energy_kwh`, `temperature_c`. Generated by `src/data_generator.py` with daily double peaks, weekend/holiday dips, weather-driven cooling/heating load, 4% growth, and deliberate mess (duplicates, gaps, sensor spikes). To use a real dataset, drop a CSV in `data/raw/energy_data.csv` and match the column names in `src/config.py`.

## Architecture
```
Raw CSV -> Cleaning -> Feature engineering -> Train 3 models + baseline -> Pick best (lowest RMSE)
                                                   |                              |
                                           Evaluation (RMSE, MAE, R2)   Recursive 7-day forecast
                                                                                  |
                              Business simulation  <-------------------------------+--> Charts + Flask API dashboard
```

```bash
pip install -r requirements.txt
```

## Usage
```bash
python runall.py            # full pipeline, then API at http://127.0.0.1:8000
python runall.py --no-api   # pipeline only
python main.py train        # or run one stage: data, clean, train, evaluate, forecast, simulate, plots, api
```

## Results (last 60 days, never seen in training)
| Model | RMSE (kWh) | MAE (kWh) | MAPE | R² |
|---|---|---|---|---|
| **Gradient Boosting** | **23.0** | 18.1 | 2.92% | **0.950** |
| Random Forest | 26.3 | 20.3 | 3.26% | 0.935 |
| Linear Regression | 31.7 | 24.5 | 3.97% | 0.905 |
| Seasonal Naive baseline | 37.8 | 27.8 | 4.60% | 0.866 |

Business simulation (₹): AI forecasts cut day-ahead procurement cost by 0.75% versus a naive plan, and shifting 10% of forecast-peak load to cheap hours cut the bill by 1.47% and lowered peak demand from 932 to 839 kWh.

## Learning outcomes
Time-series feature engineering without data leakage, chronological train/test splits, baseline comparison, recursive multi-step forecasting, translating model error into money, and serving a model through an API.

## Limitations and next steps
Data is simulated; future weather is approximated by last year's temperature. Next: real dataset (UCI household power), prediction intervals via quantile models, LSTM/Prophet comparison, Docker deployment on Render.
